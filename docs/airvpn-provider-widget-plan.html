AirVPN as a first-class VPN provider

A third VPN provider card beside Tailscale and NordVPN, backed by AirVPN Suite (bluetit + goldcrest) on Bostrom. This plan is grounded in the as-built NordVPN implementation on feature/nordvpn-live-widget, not only the NordVPN HTML plan — several patterns that matter were discovered during implementation and are not obvious from the plan alone.

Plan only — no QML yet v1.1 — as-built + gluetun recon Backend: AirVPN Suite 2.1.0 Anchor: NordVpnService / VpnService / NordVpnPanel Suite installed on Bostrom Gluetun: arr-stack device keys only User must log in with AirVPN account
Read §2 before writing any QML Copy the as-built NordVPN shapes, not a fresh invention. The NordVPN HTML plan was necessary but incomplete: the shipped code adds isReading/isMutating separation, mutation-error TTL, city fetch queues, login URL extraction, pinned titlebar/search outside the ListView, and a floating VpnHandoffCard sibling. AirVPN must inherit those fixes. Auth: Jay has a real AirVPN account. Gluetun on the arr stack only holds WireGuard device keys for that stack — not account login. The Ambxst panel must treat credentials as missing until the user logs in (writes account user/password into ~/.config/goldcrest.rc). Do not try to reuse or import the gluetun keys as a substitute for login.

2 · As-built NordVPN lessons (mandatory copy)

Tags marked as-built are patterns that exist in the shipped QML and must be reproduced for AirVPN. Citing the plan alone is not enough.

PatternWhere it livesWhy AirVPN needs it
as-built isReading vs isMutating NordVpnService.qml:47-58 Gating UI on a combined isUpdating greys out every button on each poll. Only isMutating may disable controls or reject mutations. isUpdating is spinner-only.
as-built runMutation() returns bool NordVpnService.qml:267-288, consumed by VpnService.beginHandoff Coordinator must detect "silently dropped" vs "started", or it shows "Disconnecting…" for 12 s against a command that never ran.
as-built errorFromMutation + 10 s TTL NordVpnService.qml:66-70, 432-442, 601-606 A failed connect triggers an immediate refresh; without the latch the successful status read clears lastError before VpnService's 500 ms tick sees it.
as-built CliRead component NordVpnService.qml:504-541 One shape for every read: accumulate stdout/stderr, snapshot, clear, Qt.callLater → parse. Do not paste five Process blocks.
as-built Pure .pragma library parsers + node harness nordvpn-parse.js, lab/test-nordvpn-parse.sh airvpn-parse.js + lab/test-airvpn-parse.sh. Service file must contain no string-scraping of its own.

as-built Pin titlebar + search outside ListView NordVpnPanel.qml:99-152 ListView re-lays-out its header on every model reset; model resets on every keystroke → search loses focus. Header content (cards, Quick Connect, mode) stays in ListView.header.

as-built Setup card branches on distinct blockers NordVpnSetupCard.qml available / permissionDenied / daemonReachable / needsCredentials are separate. A D-Bus denial must never offer a password form.
as-built Optimistic state = "connecting"|"disconnecting" connectTo / disconnect Applied even when already connected (country switch). Corrected by next status read.
as-built Read + mutation watchdogs 20 s / 45 s timers A wedged goldcrest/bluetit must not freeze the session latches forever.
as-built IP dropped at parser boundary nordvpn-parse.js comment block No assigned-IP property on the service. Same for AirVPN exit IPs.
as-built Deferred service init shell.qml:306-307 (2 s tier) Touch AirVpnService.available and keep VpnService.routeOwner on the deferred tier.
as-built preferredMode !== "p2p" means standard NordVpnService.p2pPreferred For AirVPN: anything other than "openvpn" means WireGuard, so a typo or old value cannot flip the default.
VpnService today is binary otherProvider(), providerConnected(), providerSettled(), and providerError() are hard-coded NordVPN ↔ Tailscale. Extending to AirVPN means making those table-driven (or switch on three ids). Do not leave a third provider half-wired through the binary helpers — that is how handoff text and settle detection will lie.

4 · Provider model — three providers, one route owner

readonly property bool tailscaleUp: TailscaleService.connected
readonly property bool nordUp:      NordVpnService.connected
readonly property bool airUp:       AirVpnService.connected

readonly property string routeOwner: {
    if (root.nordUp) return "nordvpn";
    if (root.airUp)  return "airvpn";
    if (root.tailscaleUp && TailscaleService.exitNodeId !== "") return "tailscale";
    return "none";
}
  • Replace binary otherProvider with the provider that currently owns the route (recoveryProvider / routeOwner), which VpnService already tracks during handoff.
  • providerConnected / providerSettled / providerError must switch on all three ids. For AirVPN settle, wait on !airUp && !AirVpnService.isMutating (same as Nord).
  • Already-connected AirVPN country change: call AirVpnService.connectTo directly (Nord pattern at VpnService.qml:125-128) — do not re-enter handoff.
  • Persist country-level picks only (no city/server string with spaces), into Config.system.airvpn.preferredCountry.

6 · State model and display text

// AirVpnService.qml — mirror NordVpnService derived booleans
property string state: "unavailable"
// unavailable | needsCredentials | disconnected | connecting | connected | disconnecting | error

readonly property bool connected:        state === "connected"
readonly property bool connecting:       state === "connecting"
readonly property bool disconnecting:    state === "disconnecting"
readonly property bool needsCredentials: state === "needsCredentials"
    || (available && !credentialsConfigured)

Reuse VpnService.statusTextFor(provider) direction scoping. Panel statusText mirrors NordVpnPanel.qml:38-59 (handoff first, then permission / available / daemon / credentials / connecting / …).

connect(country = "", opts = {}):
  argv = ["goldcrest", "--air-connect", "--async",
          "--network-lock", opts.networkLock === true ? "on" : "off"]
  if (opts.vpnType) argv += ["--air-vpn-type", opts.vpnType]
  if (opts.key)     argv += ["--air-key", opts.key]
  if (country)      argv += ["--air-country", country]
  return runMutation(argv)  // bool; set state "connecting" on true

9 · Hazards

  • All NordVPN §9 hazards still apply (Switch latch, StyledRect, no hardcoded colors, reuseItems reset, Icons catalog).
  • --async mandatory on connect.
  • Network Lock default off in Config and in connect argv.
  • No password on argv; no WG keys in Config/git.
  • Group membership requires session restart for Ambxst.
  • Call goldcrest only.
  • Gate controls on isMutating, never on isReading.

13 · Acceptance criteria

  • Hub shows Tailscale, NordVPN, and AirVPN with live status copy matching each panel's matrix.
  • Before login, hub and page both show Log in required; setup card explains the AirVPN account is needed and that arr-stack gluetun is separate.
  • AirVPN Quick Connect uses --async; disconnect works; country search + select works once the user has logged in.
  • Handoffs among all three are confirmed, timeout-bounded, recoverable; no cross-provider phase text.
  • Controls gate on isMutating only; titlebar/search stay focused while filtering.
  • Network Lock off by default; never enabled implicitly.
  • No secrets/IPs in Config, fixtures, logs, or git.
  • Files follow as-built NordVPN decomposition; parsers harnessed under node.
