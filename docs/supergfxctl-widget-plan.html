2. Goal & non-goals

Goal

  • Expose live supergfxctl modes in the battery bar popup, under power profiles, with identical segmented button chrome.
  • On mode selection, offer Logout, Reboot, and Dismiss so the user can complete (or abandon) the switch immediately.
  • Hide the graphics row entirely when supergfxctl / supergfxd is unavailable — no dead UI.

Non-goals (this pass)

  • No asusctl fan / Aura / battery-limit widgets (separate, Zephyrus-only work).
  • No dashboard / launcher / OSD surface for GPU mode yet.
  • No VFIO / AsusEgpu / NvidiaNoModeSet unless enumerated and explicitly opted into later — start with modes users actually switch: Integrated, Hybrid, AsusMuxDgpu.
  • No enabling supergfxd at boot on Bostrom from the shell; document only.

3. UX & interaction

1

Open popup

Battery button → existing BarPopup. Graphics row appears below profiles when service is available.

2

Pick mode

Click a non-current mode → pending highlight. Same-mode click is a no-op. Tooltips: display names.

3

Confirm

Strip appears: Logout (primary), Reboot, Dismiss. Copy mentions required action when known.

4

Apply

Logout/Reboot runs supergfxctl --mode X then the session action. Dismiss cancels pending only.

Confirm actions (commands)

ActionBehaviorCommand (align with PowerMenu)
Logout Set mode, then end graphical session so Hybrid⇄Integrated can finish. axctl system exit (same as PowerMenu logout)
Reboot Set mode, then reboot — required for AsusMuxDgpu / always_reboot. systemctl reboot
Dismiss Clear pending mode; do not call supergfxctl; collapse confirm strip; restore selection to currentMode. —
supergfxctl semantics (upstream): Switching to/from Hybrid generally requires logout; AsusMuxDgpu always needs reboot; some Integrated⇄VFIO paths are instant. The UI always offers both Logout and Reboot so the user can choose; prefer surfacing the recommended action via button emphasis (Logout primary for Hybrid/Integrated, Reboot primary for Mux).

Popup sizing

Today’s fixed contentHeight must become dynamic: 

batteryDetails   = Battery.available ? 64 : 0
profilesRow      = 36
graphicsGap      = SuperGfx.isAvailable ? (4 + optionalCaption + 36) : 0
confirmStrip     = pendingMode ? (~72) : 0
contentHeight    = sum + spacings + popupPadding * 2

Prefer binding contentHeight to mainColumn.implicitHeight + padding rather than hardcoding, so confirm expand does not clip.

Vertical bar

Battery popup already works for vertical bars via BarPopup anchoring. Keep the graphics row as a horizontal segmented row inside the popup (same as profiles) — do not mirror PowerProfileSelector’s bar-inline vertical layout for this pass.

4. Architecture

Follow the reactive singleton + Process pattern used by modules/services/PowerProfile.qml. Keep CLI parsing in the service; UI only binds to properties/methods.

SupergfxService API (proposed)

pragma Singleton
Singleton {
    property bool isAvailable: false
    property var availableModes: []          // e.g. ["Integrated","Hybrid","AsusMuxDgpu"]
    property string currentMode: ""
    property string pendingMode: ""          // UI-owned or service-owned; prefer UI
    property string requiredAction: ""       // "logout" | "reboot" | "none" | ""

    signal modeChanged(string mode)
    signal modeSetFailed(string reason)

    function initialize()
    function refresh()
    function setMode(modeName)               // Process: ["supergfxctl","--mode", modeName]
    function getModeIcon(modeName)
    function getModeDisplayName(modeName)
    function getRecommendedAction(fromMode, toMode)  // logout | reboot
}

CLI surface

IntentCommand
Presencesupergfxctl --version (or which + daemon check)
Current modesupergfxctl --get / -g
Supported modessupergfxctl --supported (prefer) or parse status
Set modesupergfxctl --mode Integrated (capitalization matters)
Do not prefix with sudo — supergfxd is a user-facing daemon; sudo is a common footgun. Surface stderr via modeSetFailed / console.warn.

UI integration point

Primary edit: modules/bar/BatteryIndicator.qml inside the existing batteryPopup ColumnLayout, after profilesRow. 

ColumnLayout {

Apply sequence (Logout example)

1. pendingMode = "Integrated"
2. on Logout click:
     SuperGfx.setMode(pendingMode)
     wait for setProc success (or fire-and-forget then action)
     Process: axctl system exit
3. On next login, SuperGfx.currentMode reflects new mode
4. If setMode fails: keep popup open, show error tint / tooltip, do not logout

Icons

  • Reuse Icons.gpu for captions / tooltips if needed.
  • Add Phosphor mappings for Integrated / Hybrid / Mux (or map Hybrid→Icons.circuitry, Integrated→Icons.cpu, Mux→Icons.gpu initially to ship faster).
  • Confirm strip: Icons.logout, Icons.reboot, and a close/dismiss glyph (Icons.minusCircle or caret — pick one existing rather than inventing).

Config

Optional later: Config.bar.showGraphicsModes default true. Not required for v1 if visibility is purely capability-gated via SuperGfx.isAvailable. If a config key is added, update both config/defaults/*.js and config/Config.qml.

Init

Defer like PowerProfile (≈2s) or piggyback the non-critical timer in shell.qml. Force-touch the singleton once so detection runs: _ = SuperGfx.isAvailable.

6. Implementation phases

Phase A Service skeleton

  • Create SuperGfx.qml with availability probe + get/list/set Processes.
  • Normalize mode names; sort Integrated → Hybrid → AsusMuxDgpu.
  • Filter out Vfio / AsusEgpu unless a future flag enables them.
  • Unit-ish check: run CLI manually on Bostrom; parse the same strings the service will.

Phase B Idle UI (read-only then click-pending)

  • Add graphics RowLayout under profiles; bind to availableModes / currentMode.
  • Match profile button styling exactly (radius selected/first/last rules, hover, tooltip).
  • Dynamic popup height; hide row when unavailable.

Phase C Confirm strip

  • Pending state, recommended primary button, Dismiss restore.
  • Wire Logout / Reboot through a small Process (copy PowerMenu pattern).
  • Only invoke session action after successful setMode (or document intentional race if daemon queues on logout).

Phase D Hardening

  • Error path when daemon down / mode rejected.
  • Optional: poll current mode on popup open.
  • Document Bostrom: start supergfxd for lab tests if not enabled at boot.
  • Validate AsusMuxDgpu path on Zephyrus only.

8. Risks & open questions

ItemNotes
Set-then-logout ordering Does supergfxctl --mode return before logout is safe, or does it wait for sessions to end? Confirm against live daemon; may need “set mode → immediately logout” without waiting on exit code 0 if the CLI blocks on logind.
Caption labels Profiles today are icon-only + tooltip. Proposal adds a quiet “Graphics” caption for discoverability. Keep profiles icon-only unless we want matching “Power” captions — decide in Phase B for visual density.
Pending in service vs UI Prefer UI-local pendingMode so dismissing does not need service state.
iGPU vendor differences Intel (Bostrom) vs AMD (Zephyrus) — service must not hardcode driver names.
Public repo No personal paths, tokens, or machine-specific absolute homes in the feature.

Success criteria

  • Battery popup shows a graphics segmented control styled like power profiles when supergfxctl works.
  • Choosing a mode presents Logout / Reboot / Dismiss; Dismiss is safe; Logout/Reboot complete the switch.
  • No UI regressions for machines without hybrid graphics tooling.
