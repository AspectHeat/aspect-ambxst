AI widget stability, rendering, and Hermes

Stop long-thread Quickshell lockups by fixing the chat data model that streaming was bolted onto, improve markdown/code rendering using end-4 patterns, and add Hermes Agent as a first-class local OpenAI-compatible provider in the assistant sidebar.

Plan only — no QML implementation yet Repo date: 2026-07-30 Surfaces: AssistantSidebar + Ai.qml Reference: end-4/dots-hyprland AiChat Hermes: OpenAI-compat API on :8642
Read §2 before rewriting the ListView The current Array.from(currentChat) pattern is not a careless mistake. It was the correct reactivity workaround for a JSON-persisted plain-object chat. Streaming made that workaround lethal. The fix must preserve on-disk chat JSON while changing the runtime model.

2 · Why it was configured this way

Timeline from git history on modules/services/Ai.qml:

WhenCommitDesign choiceWhy it made sense
2025-12-22 1cec6fb5 ai progress property var currentChat: [] of plain {role, content} Save/load is JSON.stringify / JSON.parse to chat files. QtObjects do not serialize for free.
same day same Array.from + reassign after each full reply Plain JS objects emit no QML property signals. Replacing the array is the only reliable UI notify. Project rule in AGENTS.md: raw JSON objects have no signals.
same day same Non-streaming curl -s One response → one array push. Cost is O(messages) per turn, acceptable.
2026-03-02 0e005a15 ai sidebar Always-stream via SplitParser Better UX for tokens. Data model left unchanged.
streaming path same Every chunk: clone array, set last content, reassign Necessary under the old model; catastrophic under streaming × long threads × heavy delegates.
Bottom line The architecture optimized for persistence simplicity. Streaming was layered on without introducing a reactive runtime message type. End-4 made the opposite trade: QtObjects at runtime, custom serialize for disk. That is the target here. 
Day-1 (correct for non-stream):
  reply done → Array.from(chat) → push/update → currentChat = newChat → ListView refresh once

Today (lethal under stream):
  each SSE line → Array.from(chat) → mutate last → currentChat = newChat
               → rebuild ALL message delegates
               → re-run fence regex + MarkdownText + SyntaxHighlighter on history
               → UI thread stalls → Quickshell dies

4 · Crash mechanics (what to measure)

Hot path today in modules/services/Ai.qml:

stdout: SplitParser {
  onRead: data => {
    let result = root.currentStrategy.parseStreamChunk(data);
    if (result.content) {
      root.responseBuffer += result.content;
      let newChat = Array.from(root.currentChat);
      newChat[newChat.length - 1].content = root.responseBuffer;
      root.currentChat = newChat;   // <-- full model invalidate
    }
  }
}

Compounded in AssistantSidebar.qml by:

  • Fence-splitting regex as the Repeater model expression (re-eval on every rebuild).
  • Nested Loader + inline Component per segment.
  • CodeBlock constructing SyntaxHighlighter for every code segment in history.
  • cacheBuffer: 1000 keeping heavy offscreen delegates alive.

Cost model

Roughly O(messages × chunks × (parse + layout + highlight)). A 30-turn thread with code blocks and a long streamed reply is enough to hard-lock the shell.

Success signal

While streaming, messageIDs length stays constant; only the live message’s content property changes; older delegates do not recreate.

API boundary

Strategies keep consuming plain message arrays. Add messagesForApi() that maps QtObjects → { role, content, ... } so strategy files stay mostly untouched. The mapping must retain attachments, geminiParts, functionCall, and name when present.

Content contract

  • rawContent is the canonical provider/API response; content is sanitized display text.
  • A user edit updates both fields unless the UI explicitly offers a display-only edit.
  • Hermes progress events enter neither field. Hidden reasoning needs a separate field if it must be sent back to a provider.
  • Save/load is lossless for every existing Ambxst field. Unknown JSON keys should be retained or deliberately migrated, never silently dropped.

Ownership and mutation API

Do not mutate messageIDs and messageByID ad hoc. Centralize appendMessage, removeMessageById, replaceChat, clearChat, serializeMessage, and destroyMessage. Insert the object into the map before exposing its ID; remove the ID before deleting and destroying the object. Destroy removed QtObjects on delete, clear, load, and regeneration so repeated chat changes do not leak children parented to Ai. Structural changes from process callbacks run through Qt.callLater().

  2. Compute blocks from the message object when content changes — not as an inline Repeater.model expression rebuilt from the outside.
  3. Text segments: TextEdit with MarkdownText.
  4. Code segments: existing CodeBlock.qml, but plain monospace until done; expose an explicit highlightEnabled contract and create SyntaxHighlighter through a Loader only after completion. This is an improvement over end-4, which also highlights continuously.
  5. Think segments: collapsible block (minimal styled header + body).
  6. Clipboard: replace Qt.createQmlObject(... wl-copy "...") with Quickshell.clipboardText or a properly escaped Process.
  7. Auto-scroll: capture a follow flag before content-height changes using atYEnd plus a small pixel threshold. User scrolling upward disables follow; sending a message explicitly enables it. Never force scroll on every height change.
  8. Batch streaming updates: accumulate raw chunks and flush only the live message every 30–60 ms, plus a synchronous final flush. This is required, not optional, so block parsing and layout do not run for every one-character SSE chunk.

Request behavior

  • Reuse OpenAI chat-completions streaming (thin HermesApiStrategy wrapping OpenAI, or provider branch in OpenAI strategy).
  • Send Authorization: Bearer <key>.
  • Send X-Hermes-Session-Id: <currentChatId> so Hermes can keep agent memory across turns for that Ambxst chat.
  • Model discovery: GET /v1/models when key present; fallback single model hermes-agent.
  • SSE event: hermes.tool.progress updates live toolStatus / thinking UI only — do not append into persisted assistant content.

Request lifetime contract

Each request captures a monotonically increasing generation plus the chat ID, assistant message ID, model, and strategy. Every parser, exit, and timer callback verifies that identity before writing. New chat, load, regeneration, model change, or a replacement send cancels the process where possible and always invalidates the old generation. A single idempotent finishRequest() flushes pending text, sets done, clears thinking/tool status, records any error, saves the captured chat once, and releases request state.

10 · Delivery gates

Phase 01 Message model + in-place streaming

Exit artifact: AiMessageData.qml committed; Ai.qml uses centralized ID/map lifecycle helpers; stream path no longer assigns currentChat = Array.from(...) per chunk; old attachment, Gemini, and function-message fixtures round-trip without field loss; repeated load/clear/delete destroys removed objects.

Phase 02 Sidebar bind + crash validation

Exit artifact: AssistantSidebar delegates bind to messageByID; 30–60 ms stream coalescing and request-generation guards are active; lab test script or manual protocol shows a 20+ turn / large-code stream without freeze or cross-chat writes.

Phase 03 Markdown / think / highlight gating

Exit artifact: markdown.js stateful scanner (or equivalent) passes complete, unfinished, empty, tilde, punctuation-language, and malformed think fixtures; think block UI works; highlighter is loaded only after done.

Phase 04 Hermes provider

Exit artifact: Config keys + AiPanel Hermes section; model appears when key set; chat works against local or remote Hermes /v1; tool progress shows as status only.

Gate rule Do not start Phase 04 until Phase 02’s long-thread test passes. Hermes multiplies stream volume (tools + prose); putting it on the old model will reintroduce the crash.

11 · Test protocol

  1. Smoke stream: short OpenAI/Gemini/Ollama reply; tokens appear; one assistant bubble.
  2. Long thread: 20+ turns, include large fenced code; scroll history while still streaming; no freeze.
  3. Chunk pressure: replay a response as one-character chunks; visible updates are coalesced, the final tail is present, and block parsing does not run once per character.
  4. Lossless reload: round-trip legacy fixtures containing attachments, geminiParts, function calls/results/approval state, names, and unknown optional metadata; no QtObject internals enter JSON and no fields disappear.
  5. Lifecycle: repeatedly load, clear, delete, and regenerate; removed AiMessageData objects are destroyed and the child/object count does not grow.
  6. Fence matrix: complete, unfinished, and empty backtick/tilde fences; c++, c#, and shell-session languages; missing newline; markers inside code; malformed/unfinished <think>.
  7. Request races: new chat, load chat, regenerate, change model, and replacement send during a stream; late chunks and exit handlers cannot touch or save the new chat.
  8. Completion races: SSE done then process exit, network error after partial output, cancellation, and empty response; completion occurs once and buffered output is flushed.
  9. Editing: edit, save, reload, and regenerate; content/rawContent follow the declared contract.
  10. Clipboard: copy prose and code containing quotes, newlines, backslashes, dollar signs, and shell syntax exactly.
  11. Hermes: gateway up; select Hermes; multi-turn with a tool-using prompt; status line updates; final text clean; new Ambxst chat gets a new session id header.
  12. Regression: regenerate / edit / copy / shell tool approve-reject still work.

Prefer ./lab/run-isolated.sh on Bostrom before anything that can affect the primary shell.

12 · Acceptance criteria

  • No per-chunk full-array reassignment remains in the stream path.
  • Stream fragments are coalesced to a bounded UI update rate and the final buffered tail is never lost.
  • A deliberately large streamed reply on a long history does not lock Quickshell.
  • Code fences and think blocks render correctly during and after stream across the fence matrix; SyntaxHighlighter is absent until completion.
  • Hermes is selectable, authenticated via KeyStore, and usable as a chat backend from the sidebar.
  • Old chat JSON files load without migration ceremony and round-trip without losing attachments, provider payloads, or function state.
  • Removed runtime messages are destroyed, and repeated chat replacement does not grow retained message objects.
  • Stale request callbacks cannot mutate or save a different chat.
