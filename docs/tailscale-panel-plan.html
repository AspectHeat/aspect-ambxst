Tailscale Control Panel

A built-in Tailscale panel for Aspect Ambxst: connection switching, one-click IP copy, and a peer browser — built entirely on the existing NetworkService / WifiPanel pattern so it is visually and architecturally indistinguishable from the Wi-Fi and Bluetooth panels already shipping.

Target: modules/services/TailscaleService.qml + modules/widgets/dashboard/controls/TailscalePanel.qml. Written against the repo state of 2026-07-27, Tailscale 1.98.9.

1 · Scope & interpretation

The request has three named deliverables. One of them — “connection switching” — is ambiguous in Tailscale’s vocabulary, so it is resolved into three concrete axes below. All three are in scope; they share one service and one panel.

RequestedResolved toMechanism
Connection switching A. Tailnet on/off — connect & disconnect the node tailscale up / tailscale down; state from BackendState + WantRunning
B. Exit-node selection — route all traffic via a chosen peer tailscale set --exit-node=<id>, cleared with --exit-node=; candidates from peers where ExitNodeOption == true
C. Profile / account switching — move between tailnets tailscale switch --list to enumerate, tailscale switch <name> to activate
Copy IP address Copy this node’s IPv4/IPv6/MagicDNS name, and any peer’s, from a per-row button wl-copy via Process, argv form (no shell)
Same design specification Byte-for-byte reuse of the existing control-panel idiom PanelTitlebar, StyledRect variants, Styling.*, Colors.*, Config.theme.*, Icons.* — see §5
Design anchor

Every UI decision in this plan defers to a concrete precedent already in the tree. TailscalePanel.qml mirrors WifiPanel.qml; TailscalePeerItem.qml mirrors WifiNetworkItem.qml; TailscaleService.qml mirrors NetworkService.qml; TailscalePeer.qml mirrors WifiAccessPoint.qml. Where this plan is silent on a styling detail, copy the Wi-Fi equivalent verbatim.

3 · Blocking prerequisite do first

Everything read-only works as the session user. Everything that changes state does not. Tailscale gates mutations behind root unless an operator is nominated. Without this, axes A, B and C are all dead on arrival, and the panel degrades to a read-only viewer.

# Run once per machine. Idempotent. Persists across reboots and tailscaled restarts.
sudo tailscale set --operator=$USER

# Verify — these must both succeed as the unprivileged user afterwards:
tailscale switch --list
tailscale set --webclient=false
Handle explicitly, do not assume
  • Run it on Bostrom (the test target) and on Zephyrus if the panel is to be usable there too. It is a host-level setting, not a repo change — it will not travel with a git pull.
  • The shell must never invoke sudo itself. There is no polkit agent guarantee in a Quickshell process and a hung password prompt would freeze the panel.
  • Instead the service must detect the denial. Every mutating Process parses stderr for access denied and sets TailscaleService.operatorMissing = true.
  • When operatorMissing is true, the panel shows a single non-modal inline notice — “Tailscale controls need one-time setup: sudo tailscale set --operator=$USER” — with a copy-command button, and disables toggles rather than letting them fail silently. This is the same shape as the Wi-Fi panel’s captive-portal affordance.

Secondary prerequisite, non-blocking: confirm wl-copy (wl-clipboard) is present. It already is — ClipboardService, Screenshot and ClipboardTab all depend on it — so no new dependency is introduced by the copy feature.

pragma Singleton + pragma ComponentBehavior: Bound, exactly as NetworkService.qml. Reuse that file’s asyncProcessComp / runAsync() promise helper verbatim — it is the established idiom for one-shot commands and already handles stderr capture and self-destruction.

Process topology

Process idCommand (argv)Lifecycle
availabilityProbe["which", "tailscale"]Once, on Component.onCompleted. Gates everything else.
watcher["tailscale", "debug", "watch-ipn"]Long-lived, running: root.available. SplitParser.onRead → root.refresh(). The nmcli monitor analogue — verified working unprivileged.
statusProc["tailscale", "status", "--json"]Buffer stdout across reads; parse once in onExited; diff into peers inside Qt.callLater.
prefsProc["tailscale", "debug", "prefs"]Same buffer-then-parse shape. Only source of exit-node and DNS/route prefs.
profilesProc["tailscale", "switch", "--list"]Text output, not JSON — parse defensively, tolerate the denial message. Refreshed on panel open, not on every event.
fallbackTimer—Timer, interval: Config.system.tailscale.pollInterval * 1000, running: available && watcher.running === false. Safety net only, for the case where watch-ipn dies. Default 30 s.
Two implementation traps
  • SplitParser splits on newlines. status --json is pretty-printed multi-line JSON, so it arrives in fragments. Accumulate into a property string buffer and only JSON.parse in onExited — exactly what NetworkService’s getNetworks does. Parsing per-read will throw on every line.
  • Wrap JSON.parse in try/catch. A transient partial read or a daemon restart mid-command yields invalid JSON. On failure, keep the previous model rather than clearing the list — a flickering empty peer list is worse than one stale second.

6.2 · modules/services/TailscalePeer.qml new

A plain QtObject wrapper giving each peer real QML property signals, so Behaviors and bindings in the delegate actually fire on change. Direct analogue of WifiAccessPoint.qml (19 lines) — keep it equally small.

import QtQuick

QtObject {
    id: root

    property var lastIpcObject: ({})

    property string nodeId: lastIpcObject.ID ?? ""
    property string hostName: lastIpcObject.HostName ?? ""
    property string dnsName: lastIpcObject.DNSName ?? ""
    property string os: lastIpcObject.OS ?? ""
    property bool online: lastIpcObject.Online ?? false
    property string lastSeen: lastIpcObject.LastSeen ?? ""
    property var addresses: lastIpcObject.TailscaleIPs ?? []
    property bool isExitNode: lastIpcObject.ExitNode ?? false
    property bool exitNodeOption: lastIpcObject.ExitNodeOption ?? false
    property string relay: lastIpcObject.Relay ?? ""

    readonly property string ipv4: addresses.length > 0 ? addresses[0] : ""
    readonly property string ipv6: addresses.length > 1 ? addresses[1] : ""
    readonly property bool isSelf: false
}

Identity for the resync diff is nodeId — stable across renames and IP changes, unlike the ssid/bssid/frequency triple Wi-Fi has to use. This makes the diff loop simpler than NetworkService’s: one Map keyed by node ID.

6.3 · modules/widgets/dashboard/controls/TailscalePanel.qml new

Structurally a clone of WifiPanel.qml: root Item, maxContentWidth / contentWidth / sideMargin, a full-bleed ListView with the titlebar in its header, a centered empty state.

Header composition (top to bottom, inside ListView.header)

  1. PanelTitlebar
    • title: "Tailscale"
    • statusText — precedence: lastError → "Setup required" (operatorMissing) → "Log in required" → "Connecting…" → "Exit node: <name>" → "<n> of <m> online"
    • statusColor — Colors.error for errors, Colors.warning for setup/login, otherwise Styling.srItem("overprimary"). Same conditional shape as WifiPanel.qml:52.
    • showToggle: true, toggleChecked: TailscaleService.connected, onToggleChanged: TailscaleService.toggle()
    • actions: Icons.globe (clear exit node — enabled: exitNodeId !== ""), Icons.popOpen (admin console), Icons.sync (refresh, loading: isUpdating)
  2. Self card — a StyledRect variant: "internalbg", Styling.radius(4), holding this node’s hostname, MagicDNS short name, IPv4 and IPv6, each row with a trailing copy button (§7). This is the primary “copy my IP” surface and belongs above the fold.
  3. Exit-node row — an OptionsMenu (modules/components/OptionsMenu.qml, already used by other panels) listing None (direct) plus exitNodeOptions. Visible only when exitNodeOptions.length > 0, so it self-hides on tailnets with no exit nodes — which is the current state of this tailnet (§11).
  4. Profile row — a second OptionsMenu over profiles, visible only when profiles.length > 1. Switching profiles is disruptive, so the selection triggers an inline confirm (reuse ContextMenu) rather than firing immediately.
  5. Setup notice — visible only when operatorMissing. StyledRect variant: "common", Colors.warning text, plus a copy button that puts sudo tailscale set --operator=$USER on the clipboard.
  6. Peer list header — a small "Devices" label, matching the type scale of the secondary line in WifiNetworkItem (Styling.fontSize(-2), Colors.overSurfaceVariant).

Body

7 · Copy-to-clipboard UX

Copy targets: this node’s IPv4, IPv6 and MagicDNS name (from the self card); every peer’s IPv4, IPv6 and MagicDNS name (from an expanded row); and the operator setup command (from the setup notice).

Mechanism

All existing call sites shell out and string-interpolate — e.g. ClipboardTab.qml:596 and CodeBlock.qml:71, the latter building QML source at runtime via Qt.createQmlObject. Do not copy that pattern here. Peer hostnames on this tailnet already contain a typographic apostrophe, and a shell-quoted path through bash -c is an unnecessary injection surface for data that arrives from the network.

Process {
    id: copyProc
    // argv form: no shell, no quoting, no escaping bugs
    command: ["wl-copy", "--", ""]
}

function copyText(text) {
    if (!text || text.length === 0)
        return;
    copyProc.command = ["wl-copy", "--", text];
    copyProc.running = true;
    root.copied(text);
}

Feedback

There is no toast or snackbar primitive in this codebase — modules/shell/osd/ is bound to volume/brightness and Notifications.qml is a D-Bus server (it receives notifications, it does not send them). Introducing a toast system for one button is out of proportion.

Use a transient in-button state instead: the copy button’s glyph swaps Icons.copy → Icons.accept and its color to Styling.srItem("overprimary") for 1200 ms, driven by a per-button Timer. Colour and opacity transitions go through the standard Behavior … enabled: Config.animDuration > 0 guard. Each button additionally carries a StyledToolTip reading “Copy IPv4 address” etc., matching PanelTitlebar’s action buttons.

Optional, deferred

If a system-wide confirmation is ever wanted, notify-send via Quickshell.execDetached reaches the shell’s own notification server and needs no new infrastructure. Left out of the initial build: it is noisy for an action the user just performed deliberately, and it adds a runtime dependency on libnotify.

The copyFormat config key selects which value the primary click copies when a row is collapsed (ipv4 | ipv6 | dnsname), so a user who lives in MagicDNS names is not forced through the expand step. Expanded rows always offer all three explicitly.

8 · Connection switching — command reference

ActionCommand (argv)Notes
Connect["tailscale", "up"]Blocks until the daemon settles or the login URL is needed. Run through runAsync; on NeedsLogin fall through to login().
Disconnect["tailscale", "down"]Fast. Keeps the node logged in — this is a connection toggle, not a logout.
Log in["tailscale", "login"] detachedQuickshell.execDetached, never runAsync — it opens a browser and can hang indefinitely.
Set exit node["tailscale", "set", "--exit-node=" + id]Accepts a node ID, IP or MagicDNS name. Prefer the node ID: stable across renames.
Clear exit node["tailscale", "set", "--exit-node="]Empty value is the documented clear form.
Exit-node LAN access["tailscale", "set", "--exit-node-allow-lan-access=true"]Only meaningful with an exit node set; disable the switch otherwise.
List profiles["tailscale", "switch", "--list"]Human-readable table, not JSON. Parse tolerantly; treat any parse failure as “no profiles”.
Switch profile["tailscale", "switch", name]Tears down and re-establishes the tunnel. Confirm before firing; expect several seconds of churn and a burst of watch-ipn events.

Every mutating call follows one shape: set isUpdating = true, runAsync(...), then refresh() and clear the flag in both .then and .catch — the structure of NetworkService.enableWifi() at lines 103-112. In .catch, test the message against /access denied/i to set operatorMissing, else store it in lastError.

9 · Phased delivery

Each phase ends at a commit that leaves the shell bootable. Sequenced so the risky part (mutations, which can drop the SSH path to the test machine) lands after the read-only surface is proven.

P0 Prerequisites ~10 min · no code

  • sudo tailscale set --operator=$USER on Bostrom; verify switch --list and set now work unprivileged.
  • Same on Zephyrus if the panel is to be exercised there.
  • Record the outcome in learning/ — it is a host-level fact that will not be obvious from the repo later.

P1 Service, read-only ~3 h · no UI

  • TailscalePeer.qml in full.
  • TailscaleService.qml: availability probe, statusProc, prefsProc, watcher, debounce timer, peer diff/resync, friendlyPeers, exitNodeOptions.
  • No mutating verbs yet. No panel yet.
  • Verify by touching TailscaleService.peerCount from a throwaway Component.onCompleted console.log in shell.qml, run under lab/run-isolated.sh, then remove the probe before committing. (Log the count, never the peer data — public repo, and logs get pasted.)

P2 Panel, read-only + copy ~4 h

  • TailscalePanel.qml — titlebar, self card, peer ListView, empty states. Toggle rendered but disabled.
  • TailscalePeerItem.qml — collapsed row, expansion, address rows.
  • copyText() + the swap-glyph feedback. “Copy IP” is complete at the end of this phase.
  • Settings wiring: SettingsTab.qml and SettingsIndex.qml, section: 10.
  • Verify visually over Moonlight; side-by-side against the Wi-Fi panel for type scale, row height, radius and hover tint.

P3 Mutations — the three switching axes ~3 h

  • Axis A: up()/down()/toggle(), wired to the titlebar toggle. needsLogin path.
  • Axis B: setExitNode()/clearExitNode(), exit-node OptionsMenu, per-peer action buttons, LAN-access switch.
  • Axis C: profilesProc, switchProfile(), profile menu with confirm step.
  • operatorMissing detection, the setup notice, and disabled-state handling throughout.
  • Verify — see the SSH warning in §10 before testing the disconnect path.

P4 Quick controls + config ~1.5 h

  • QuickControls.qml: button, expandedPanel === 2, third Loader, index-relative slide maths.
  • Config keys in both config/defaults/system.js and config/Config.qml.
  • Verify the three-way panel slide animates coherently in both directions, and that a clean profile (delete the sandbox system.json) regenerates with the new keys.

P5 Polish ~2 h · optional

  • Peer search/filter via SearchInput once the list exceeds ~10 rows.
  • Collapsible “Offline” group.
  • Relative LastSeen formatting (“3 h ago”).
  • Rx/Tx byte counters on expanded rows.
  • acceptRoutes / acceptDNS / shieldsUp as switches.

Total for P0–P4 (the full request): roughly 11–12 hours. The copy-IP deliverable is usable after P2; connection switching after P3.

10 · Test protocol

Per CLAUDE.md: author and commit on Zephyrus, pull and run on Bostrom. Never edit in the Bostrom checkout.

# Zephyrus — authoring
git switch -c feature/tailscale-panel
# … edit, commit …
git push -u origin feature/tailscale-panel

# Bostrom — test target
ssh bostrom
cd ~/Projects/aspect-ambxst
git fetch origin && git switch feature/tailscale-panel

# Sandboxed run FIRST — never let an untested change reach boot
./lab/run-isolated.sh
# logs: ~/.local/state/ambxst-lab/latest.log
Testing disconnect will cut your own SSH session

Bostrom is reachable as ssh bostrom over the Tailnet. tailscale down — the P3 toggle — kills that path instantly, and the panel that would turn it back on is on the other side of it.

Before exercising axis A:

  • Connect via ssh bostrom-lan instead, which survives the tunnel dropping.
  • Keep a Moonlight session open as the visual channel, independent of SSH.
  • Recovery from the console if needed: sudo tailscale up.
  • Same caution for axis C — a profile switch changes which tailnet the node is on, so the bostrom host alias may resolve differently or not at all afterwards.

11 · Risks & caveats

RiskSeverityMitigation
Operator not set — every mutation denied high P0 handles it. The service detects and surfaces it rather than failing silently; the panel stays useful read-only. See §3.
No exit nodes on this tailnet — axis B cannot be tested end-to-end med Confirmed empty as of 2026-07-27. Options: advertise one temporarily from Zephyrus (sudo tailscale set --advertise-exit-node, then approve it in the admin console), or develop against a JSON fixture with synthetic values. Build it regardless — the UI self-hides when the list is empty, so shipping it untested is low-risk, but say so explicitly in the PR rather than implying it was verified.
Disconnect severs SSH to the test host high ssh bostrom-lan + Moonlight before touching axis A. See §10.
Leaking tailnet identifiers into a public repo high No fixtures with real data, no peer names in console.log, grep gate in the pre-commit check (§10). Already burned this repo once.
Shell injection via peer hostname med argv-form Process.command everywhere. Never bash -c with an interpolated peer field. A real peer name already contains a non-ASCII apostrophe.
watch-ipn is an undocumented debug subcommand med Verified working on 1.98.9, but no stability guarantee across upgrades. The fallbackTimer covers its disappearance; if watcher exits non-zero at startup, log once and fall back to polling rather than retrying in a loop.
Upstream merge conflict in the four edited files med Upstream touches SettingsTab.qml and QuickControls.qml occasionally. All edits are pure appends at the end of lists, which conflict cleanly and resolve trivially. Keeping the new panel’s logic in new files rather than extending NetworkService is deliberate for this reason.
switch --list output format changes low Text, not JSON. Parse defensively; on any unexpected shape produce an empty profiles list, which hides the profile row entirely.
Panel added to the boot-critical shell med Ambxst is Bostrom’s primary shell; a QML error can cost the desktop. Every phase is tested under lab/run-isolated.sh first. available gating means a machine without Tailscale never constructs the panel. The Noctalia fallback in autostart-shell.sh remains the backstop.
Hardware divergence none Unlike the asusctl/supergfxctl work, Tailscale is pure userspace networking with identical 1.98.9 builds on both machines. This feature is fully validatable on Bostrom.

12 · Out of scope

  • Taildrop file transfer — needs a file picker and a receive-side handler; a feature in its own right.
  • Serve / Funnel management — a configuration surface far larger than a control panel.
  • Subnet-route advertisement and approval — inherently an admin-console operation.
  • SSH-into-peer — belongs in the launcher, not a network panel.
  • ACL / policy viewing — read-only web surface; Icons.popOpen to the admin console covers the need.
  • Bar indicator widget — plausible follow-up, but the bar’s widget registry is a separate wiring surface with its own config schema. The quick-control button already gives at-a-glance state.
  • Fixing the SettingsIndex.qml numbering drift — pre-existing upstream bug; see §6.5.

13 · Acceptance criteria

  1. A Tailscale section appears in the dashboard settings sidebar with Icons.vpn, and its panel loads lazily like every other section.
  2. The panel’s titlebar toggle connects and disconnects the node, and the displayed state re-converges within ~2 s of an external tailscale up/down.
  3. An exit node can be selected and cleared from the panel, from both the header menu and a peer row; the active exit node is visible in the titlebar status and badged in the list.
  4. When more than one profile exists, a profile switcher is present and switching works after confirmation.
  5. This node’s IPv4, IPv6 and MagicDNS name are each copyable in one click, with visible confirmation, and the same is true for every peer.
  6. Peers list with hostname, OS icon, online state and exit-node capability, sorted online-first.
  7. The panel is visually indistinguishable in idiom from WifiPanel: same titlebar, row height, radii, type scale, hover tint and animation timing. No raw Rectangle, no hardcoded color, size or radius anywhere in the diff.
  8. With the operator unset, the panel is read-only and says so, with a copyable fix — it never fails silently.
  9. On a machine without the tailscale binary, the section and quick-control button are absent and no processes are spawned.
  10. New config keys exist in both config/defaults/system.js and config/Config.qml, and a clean profile regenerates cleanly.
  11. lab/run-isolated.sh runs clean: no QML warnings, no measurable idle CPU increase.
  12. The diff contains no tailnet names, node IDs, CGNAT addresses, hostnames, emails or absolute home paths.
