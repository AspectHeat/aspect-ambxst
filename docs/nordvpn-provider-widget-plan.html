NordVPN as a first-class VPN provider

A NordVPN country browser and connection flow beside the existing Tailscale provider, with a deliberate, serialized handoff between mesh access and commercial VPN egress. This is v2: it supersedes the v1 plan, which was implemented and then reverted.

Plan only — no QML implementation Supersedes v1 (2026-07-29) Repo state: 2026-07-30 Design anchor: TailscalePanel + TailscalePeerItem Backend: NordVPN Linux CLI only
Read this before writing any QML v1 was a good-looking plan that produced unusable code. The failure was structural, not effort-related: the plan specified a UI its own data source could not feed, and it had no phase gates, so the contradiction was resolved at the keyboard by improvising a network dependency. §2 and §3 exist to prevent a repeat. Do not skip to §7.

1 · Product outcome

The VPN settings entry remains a provider hub. Tailscale and NordVPN each get their own provider page and share a thin coordination layer so the primary toggles behave predictably. Tailscale keeps devices, exit nodes, and profiles. NordVPN exposes Quick Connect, a searchable flagged country list with city drill-down, a Standard/P2P group selector, connection details, and a small set of safe preferences.

2 · Why v1 failed — and what changed here

v1 shipped as commits de755246, 82624989, 46de5791, 800f520f, then was reverted. The defects were symptoms; these were the causes.

Root cause in v1Consequence observedFix in v2
The plan contradicted itself. §3's mock showed per-server load and 26 ms latency; §5 specified a CLI-only service that exposes neither. The implementer reached for api.nordvpn.com over curl to obtain load, and silently dropped latency entirely. The server feed was then fetched over the very link the VPN was tearing down, so switching produced "feed unavailable" errors. §3 data availability matrix. Every UI element is bound to a named field from one source, with an explicit degradation rule. Nothing may appear in a mock that §3 does not feed.
No phase exit artifacts. Five phases were listed; none had a deliverable that would show up in a diff. Phase 01 (recon) and Phase 02 (fixtures) were skipped invisibly. Parsers were written against a guessed CLI surface. §10 gates. Each phase names a committed artifact. A missing artifact blocks the next phase and is visible in review.
The contract was pre-written, then "verified". §5 listed exact commands and parse targets hedged with "re-verify during Phase 1". Implementation anchored to guesses. When reality diverged there was a contract to satisfy and no data. §5 is a template with blanks. Phase 01 fills it from real redacted output. The blanks are the gate.
The plan's own pseudocode taught an anti-pattern: phase = "disconnecting-current". VpnService.qml branched on phase.startsWith("Disconnecting") — display text used as the state variable, never cleared on external change. §6. An enum that is never rendered, plus a pure mapping function for text, plus direction scoping.
Zero QML-internal risks. The risk table covered CLI drift, privileges, routing, fonts, licensing — all external. Every bug actually hit was QML-internal: Switch binding destruction, stale transient state, direction-blind status text. §9 hazards, each with an in-repo precedent that already solves it.
No state × surface copy matrix. Undefined cells rendered whatever was left in memory — e.g. the NordVPN page displaying "Disconnecting Tailscale…" as its own status. §7.3. All 7 states × 3 surfaces have defined copy.
No decomposition budget. NordVpnCountryItem.qml was named but nothing forced extraction. A 613-line panel: ~340-line inline ListView header, ~155-line inline delegate, 12 levels of nesting. §8 budgets with hard limits and a named file per concern.
Providers modeled as symmetric. A single activeProvider string and mutually exclusive toggles. TailscaleService.connected means "daemon Running"; NordVpnService.connected means "owns default route". Conflating them let a toggle read off while the coordinator believed Tailscale was up. §4. Two independent connection booleans plus a separately observed route owner.

4 · Provider model — the two are not symmetric

v1's single activeProvider string was wrong because the two services mean different things by "connected". Model three independent facts instead.

// VpnService.qml
readonly property bool tailscaleUp:  TailscaleService.connected        // daemon Running; mesh reachable
readonly property bool nordUp:       NordVpnService.connected          // tunnel established

// Who actually owns the default route, as observed - not as intended.
readonly property string routeOwner: nordUp ? "nordvpn"
    : (tailscaleUp && TailscaleService.exitNodeId !== "" ? "tailscale" : "none")

Consequences that must be respected in the UI:

  • Tailscale being up is not a reason to disconnect it. It only owns egress when an exit node is set. A handoff to NordVPN is only required when routeOwner === "tailscale".
  • Both may legitimately be connected at once — Tailscale for peer/subnet access, NordVPN for egress. The hub must be able to render that state without calling it an error.
  • The user can operate either CLI outside Ambxst. The coordinator makes the default interaction safe; it never asserts a state it has not observed.
Do not promise mutual exclusion An "Allow simultaneous connections" setting may only be added after lab testing proves routing and DNS behavior on Bostrom. Until then the UI defaults to a serialized handoff but still reports observed reality.

  • nordvpnd-killswitch.service is loaded and active (exited) even though nordvpn settings reports Kill Switch: disabled. Unit state is not a kill-switch signal — read it only from nordvpn settings.

Refresh strategy

NordVPN has no documented event stream, so unlike TailscaleService (which uses tailscale debug watch-ipn as a push source with a poll only as fallback) this service must poll. Follow the visibility-gated idiom already used by BluetoothService.qml:246-253 rather than inventing a second interval config key:

Timer {
    id: pollingTimer
    interval: Math.max(5, Config.system.nordvpn.pollInterval) * 1000
    repeat: true
    running: root.available && root.enabled && !SuspendManager.isSuspending
        && (GlobalStates.dashboardOpen || GlobalStates.launcherOpen || GlobalStates.overviewOpen
            || root.connected || VpnService.handoffPhase !== "idle")
    onTriggered: root.refresh()
}

Mandatory companions, each with an in-repo precedent:

  • 200 ms debouncer in front of the public refresh(), with the real work in performRefresh() — TailscaleService.qml:269-274. v1 lacked this and dropped refreshes via if (statusProc.running) return.
  • Multi-process bookkeeping via a refreshPartsRemaining counter and finishRefreshPart() — TailscaleService.qml:92-106. isUpdating must not clear until every part has landed. v1 cleared it on a 900 ms timer before the status reparse, and the coordinator polled that flag.
  • Suspend awareness via a Connections on SuspendManager — NetworkService.qml:22-32. Neither VPN service had this; resume is exactly when tunnel state goes stale.
  • Immediate refresh after each mutation and on panel open.

Parser hardening

  • Parsing lives in pure functions in modules/services/nordvpn-parse.js, each taking a string and returning a plain object. Raw CLI text never reaches a UI component, and the service does no parsing inline. See the quarantine rule in §10.0 — this file is the only place recon may change.
  • Match labels case-insensitively, tolerate reordered and missing lines, and always fall back with ?? default per modules/services/AGENTS.md:35.
  • Force environment: ({ LANG: "C.UTF-8", LC_ALL: "C.UTF-8" }) so labels are stable — TailscaleService.qml:421-424.
  • Never let an unrecognized status silently mean "disconnected." v1's else state = "disconnected" clobbered loggedOut. Unknown input maps to "error" with the raw line in lastError.
Privacy: nordvpn status includes your assigned IP It must never be persisted, logged, or committed. If it is displayed at all, it follows the Tailscale concealment idiom (TailscalePeerItem.qml ipv4Revealed: hidden by default, revealed on explicit user action, never in a screenshot-able default state). Fixtures must be scrubbed of IPs, account names, and real server history.

6 · State model and display text

6.1 Service state — a normalized enum

// NordVpnService.qml - mirrors the TailscaleService derived-boolean idiom
property string state: "unavailable"
// domain: unavailable | loggedOut | disconnected | connecting | connected | disconnecting | error

readonly property bool connected:     state === "connected"
readonly property bool connecting:    state === "connecting"
readonly property bool disconnecting: state === "disconnecting"
readonly property bool needsLogin:    state === "loggedOut"

v1 declared this domain but never produced "disconnecting", so there was no state to render during teardown. Set it optimistically when the disconnect mutation is issued and let the next status read confirm or correct it.

6.2 Handoff state — an enum that is never rendered

// VpnService.qml
property string handoffPhase: "idle"      // idle | confirming | disconnecting | connecting | failed
property string handoffTarget: ""         // "" | "nordvpn" | "tailscale"
property string lastError: ""

// Text is DERIVED, and scoped to the asking surface. A panel never reads handoffPhase directly.
function statusTextFor(provider): string {
    if (handoffTarget !== provider)
        return "";                        // <-- the v1 "Disconnecting Tailscale..." bug, fixed
    switch (handoffPhase) {
    case "disconnecting": return "Disconnecting " + labelFor(otherProvider(provider)) + "…";
    case "connecting":    return "Connecting "    + labelFor(provider) + "…";
    case "failed":        return lastError;
    default:              return "";
    }
}

Three rules follow, and they are the fix for the artifacts users reported:

  • Never branch on display text. No phase.startsWith(...). Branch on the enum.
  • Scope by direction. A surface only renders phase text when it is the handoff target. This is why the NordVPN page could show "Disconnecting Tailscale…".
  • Transient state must be cleared on entry, not only on exit. Clear handoffPhase, handoffTarget and lastError when a provider page mounts and when an external state change is observed. v1 rendered lastError indefinitely.

6.3 Handoff sequence

requestProvider(target):
  if target already connected:            open target page          // no mutation
  else if routeOwner === "none" or routeOwner === target:
                                          connect(target)           // nothing to hand off
  else:
      handoffPhase = "confirming"         // Config.system.vpn.handoffPolicy === "confirm"
      on confirm:
        handoffPhase = "disconnecting";   disconnect(routeOwner)
        await disconnected                timeout 12 s
        handoffPhase = "connecting";      connect(target, remembered selection)
        await connected                   timeout 25 s
        handoffPhase = success ? "idle" : "failed"

Use two independently-bounded waits, not v1's single 500 ms × 50 loop shared by both legs. During a handoff both provider cards are disabled and only the target card shows phase text. Cancellation is unavailable once disconnect begins. On failure, do not silently reconnect the prior provider — surface a "Reconnect Tailscale" recovery action so no network mutation is a surprise.

The confirmation reuses the existing context-menu idiom rather than a new dialog type — TailscalePanel.confirmProfile() calls Visibilities.contextMenu.openCustomMenu([...]) with accept/cancel entries (Icons.accept / Icons.cancel).

9 · Repo conventions and QML hazards

Each hazard below caused a real v1 defect and each already has an in-repo solution. Cite the precedent in the implementing commit.

9.1 Switch destroys its own checked binding

Qt Quick Controls assigns checked imperatively on click, which destroys checked: root.toggleChecked. After the first interaction the switch stops tracking the service — the toggle position becomes a lie. This is why a Tailscale toggle could read "off" while the coordinator believed Tailscale was up.

The repo already solves this in ShellPanel.qml:149-222 (component ToggleRow, copied in CompositorPanel.qml:100-153 and SystemPanel.qml:1107): bind only the outer property, re-push to the inner Switch imperatively in onCheckedChanged, and guard the echo with a _updating re-entrancy latch.

property bool _updating: false
onCheckedChanged: {
    if (!_updating && toggleSwitch.checked !== checked) {
        _updating = true;
        toggleSwitch.checked = checked;      // imperative, not a binding
        _updating = false;
    }
}

Action: fix PanelTitlebar.qml so every panel using showToggle is corrected at once. Treat it as a prerequisite commit (Phase 01), separable and independently reviewable.

The titlebar needs a narrower fix than a full ToggleRow port ToggleRow detects user intent with Switch.onCheckedChanged, so it needs the latch to suppress an echo. PanelTitlebar already uses onToggled (:121), which Qt emits only for user interaction — an imperative checked assignment raises checkedChanged but not toggled. So the emit side is already correct and must be left alone; only the tracking side is broken. Add the re-assert on onToggleCheckedChanged and keep the latch as re-entrancy defense. Do not "simplify" this by switching to onCheckedChanged — that reintroduces the echo the latch exists to catch, and turns every external state change into a spurious command.

9.2 Service-layer rules (modules/services/AGENTS.md)

  • pragma Singleton + pragma ComponentBehavior: Bound; Singleton { id: root }; all cross-scope writes qualified root.x.
  • Qt.callLater() when modifying lists or models inside Process handlers — explicitly required (:33) and listed as an anti-pattern when omitted (:39).
  • Capture the buffer into a const and clear it before the deferred parse, so the closure reads a stable snapshot.
  • Lists are readonly property list<T> mutated in place and reconciled by identity — splice removals with destroy(), update survivors, push new, then recompute derived views in one assignment. See TailscaleService.syncPeers() at :122-155. v1 reassigned plain arrays wholesale.
  • Derived/sorted views are plain property list<var> reassigned once so a single change notification fires; always [...list].sort(...).
  • SplitParser for both stdout and stderr; never StdioCollector in this service family.
  • Mutations funnel through one runMutation() guarded by if (!available || !enabled || isUpdating) return;. Clear lastError at mutation start. Re-read in both .then and .catch.
  • Promote recognized failure classes into their own boolean instead of dumping a raw string at the user — TailscaleService.handleMutationError() at :157-165 does this for operatorMissing. Do the same for a NordVPN permission/group error, with one-time setup guidance. Never embed sudo in a UI mutation.

9.3 Widget-layer rules

  • pragma ComponentBehavior: Bound on line 1 of every panel and item file. 4-space indent. Alphabetized qs.* imports.
  • Never a raw Rectangle container — StyledRect with a variant. Never hardcode a color, radius, or font size: use Colors.*, Styling.radius(), Styling.fontSize(). v1 violated this at NordVpnPanel.qml:549 (radius: 2).
  • Never set both variant and color on a StyledRect — color is a computed binding off the variant. v1 did this at NordVpnPanel.qml:545-551.
  • Hover is variant: mouseArea.containsMouse ? "focus" : "common".
  • Delegates: thin full-width Item with required property var modelData, hosting the extracted item at width: root.contentWidth, horizontally centered.
  • With reuseItems: true, reset local UI state when the model object changes — TailscalePeerItem.qml:47-50 (onPeerChanged). Otherwise a revealed IP or expanded row leaks onto the next country as you scroll.
  • Null-check nested properties (root.country?.code ?? "").
  • Animate via Behavior on X { enabled: Config.animDuration > 0; ... }.
  • JSON.parse() results have no QML signals — never use one as a Connections target.
  • Icons must exist in modules/theme/Icons.qml. Available and relevant: vpn, globe, lightning, shield, shieldCheck, sync, caretLeft, caretRight, mapPin, gear, lock, accept, cancel, alert, info. There is no Icons.warning or Icons.check — use alert and accept.

9.4 Reuse, don't reimplement

v1 correctly reused SearchInput, SegmentedSwitch, PanelTitlebar and StyledRect. Keep that. Note there is deliberately no shared styled-button or badge component — the repo norm is an inline Button with a background: StyledRect and a contentItem: Text. Match the existing idiom rather than inventing a component, but if the same badge appears three times, extract it and say so in the commit.

One caveat: SegmentedSwitch.currentIndex self-assigns on click, so a binding to it breaks exactly as in §9.1. Re-derive from config in onIndexChanged (as v1 did) or apply the latch.

11 · Test protocol

11.1 The fixture harness — runnable, not a checklist

v1's test protocol was a list of good intentions with no way to execute it. Parsers here are plain JavaScript in modules/services/nordvpn-parse.js with no QML dependencies, which makes them testable without Quickshell, a compositor, or a NordVPN subscription. That is the whole reason for the quarantine in §10.0.

lab/test-nordvpn-parse.sh          # runs the harness; exits non-zero on any mismatch
lab/fixtures/nordvpn/
    status-connected.txt           # each .txt pairs with a .expected.json
    status-connected.expected.json
    status-disconnected.txt
    status-logged-out.txt
    countries.txt
    cities-united-states.txt
    groups.txt
    settings.txt
    status-garbage.txt             # adversarial: must yield state "error", never "disconnected"

The harness strips the leading .pragma library line, loads the file in node, runs each parser over its fixture, and deep-compares against the .expected.json. Adding a fixture is therefore adding a test. Keep it in lab/, which is ours alone and will never conflict on upstream sync.

Service — against fixtures

  • CLI missing; daemon stopped; logged out; no subscription
  • Connected, disconnected, connecting, disconnecting parses
  • Truncated, reordered, empty, and localized output
  • Unknown status string → error, never disconnected
  • Country names with spaces and underscores; non-ASCII names
  • Mutation timeout and non-zero exit
  • No overlapping Process mutations
  • Permission/group error → setup guidance, not a raw string

Interface

  • 480 px settings and compact popup widths
  • Empty, filtered, and long-list states
  • Emoji flag vs ISO badge fallback under the configured font
  • Keyboard focus, search, scroll reset
  • Scroll a long list with reuseItems — no leaked row state
  • Light and dark theme variants; no hardcoded values
  • Every §7.3 cell rendered

Routing and handoff

  • Tailscale → NordVPN and the reverse
  • Cancel before handoff begins
  • Disconnect succeeds, target fails → recovery action works
  • External CLI state change reflected in the UI
  • Tailscale up without an exit node → no handoff prompt (§4)
  • DNS, LAN, MagicDNS, peer reachability after each transition

Safety

  • Kill switch behavior during a transition; never toggled implicitly
  • Settings panel closed mid-mutation
  • Quickshell restart while connected
  • Suspend and resume while connected
  • Sandboxed HOME under lab/
  • No IP, account name, or credential in any log, fixture, or commit

13 · Acceptance criteria
