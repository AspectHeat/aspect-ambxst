NordVPN as a first-class VPN provider

Add a NordVPN country browser and speed-oriented connection flow beside the existing Tailscale provider, with a deliberate one-click handoff between mesh access and commercial VPN egress.

Plan only — no QML implementation Repo state: 2026-07-29 Design anchor: current Tailscale panel Backend: official NordVPN Linux CLI

1 · Product outcome

The VPN settings entry remains a provider hub. Tailscale and NordVPN each receive a separate provider menu, but share a small coordination layer so the primary toggle behaves predictably. Tailscale continues to expose devices, exit nodes, and profiles. NordVPN exposes Quick Connect, countries with flags, a P2P-optimized mode, connection details, and a compact set of safe connection preferences.

Recommended interaction model Clicking an inactive provider asks for a handoff only when the other provider currently owns the default route. On confirmation, disconnect the old provider, wait for its disconnected state, then connect the new provider. Never issue both mutations at once.

2 · What the recent Tailscale integration established

The commits from 23d80351 through bc124e90 created the architecture this feature should extend, not replace:

  • VpnPanel.qml is already a provider landing page with currentSection routing and lazy loading.
  • SettingsTab.qml maps subsection tailscale to settings section 10; SettingsIndex.qml adds searchable deep links.
  • TailscaleService.qml owns CLI availability, read state, mutations, errors, and refresh lifecycle.
  • TailscalePanel.qml is reusable in full settings and compact tray contexts.
  • Configuration lives in both config/defaults/system.js and config/Config.qml.
  • Recent polish added privacy concealment, stable direct routes, popup scroll reset, and header anchoring. NordVPN should inherit those lessons on its first pass.
Scope boundary Do not merge NordVPN semantics into TailscaleService. The providers have different state models and CLI lifecycles. Coordination belongs in a thin VpnService; provider details remain in separate services.

Provider landing page

  • Keep the existing PanelTitlebar("VPN") and “Providers” label.
  • Add a NordVPN card beneath Tailscale. Each card shows availability, connection state, one-line purpose, and a caret. The whole card opens its submenu.
  • Show “Not installed” inline rather than hiding a configured provider. Hide the entire VPN sidebar section only when no provider is enabled/available.
  • A compact handoff strip appears only while one provider is connected. It names the current route owner and the alternative action.

NordVPN provider page

  • Header: back, logo/name, state dot, primary toggle, refresh action.
  • Connected card: country flag, country/city/server, technology, elapsed time if reliably available, and Disconnect.
  • Disconnected card: “Quick Connect” primary action using the last selected mode and country preference.
  • Mode selector: Fastest and P2P optimized. Explain that standard servers support P2P too; optimized mode explicitly requests the CLI P2P group.
  • Country list: sticky search, Quick Connect pseudo-row, then alphabetized countries. Current country rises beneath Quick Connect while connected.
  • Advanced options collapsed by default: technology (NordLynx/OpenVPN), kill switch, auto-connect, LAN discovery. Do not expose every CLI knob in v1.

4 · Tailscale ↔ NordVPN handoff state machine

requestProvider(target):
  if target is already connected:
      open target panel                        // no mutation
  else if no other provider is connected:
      connect(target)
  else:
      show confirmation:
        "Switch from Tailscale to NordVPN?"
      on confirm:
        phase = "disconnecting-current"
        disconnect(current)
        wait for disconnected, timeout 12 s
        phase = "connecting-target"
        connect(target, remembered selection)
        wait for connected, timeout 25 s
        phase = success ? "idle" : "failed"
Do not promise perfect mutual exclusion The user can operate either CLI outside Ambxst, and Tailscale may be useful simultaneously for subnet/peer access while NordVPN owns the default route. The coordinator should make the default UI safe, but report observed reality. Add an “Allow simultaneous connections” advanced setting only after lab testing proves routing and DNS behavior.

During a handoff, both provider cards are disabled, the target card shows the current phase, and cancellation is unavailable once disconnect begins. If connecting the target fails, do not silently reconnect the prior provider; show a clear recovery action (“Reconnect Tailscale”). This avoids an unexpected network mutation.

5 · NordVPN service contract

NordVpnService.qml follows the reactive singleton pattern and uses argv-form Process.command exclusively. No shell interpolation is needed.

SurfaceMeaning / source
availablewhich nordvpn succeeded.
loggedInDerived conservatively from nordvpn account; never store credentials.
stateNormalized enum: unavailable, loggedOut, disconnected, connecting, connected, disconnecting, error.
country / city / serverParsed from nordvpn status; empty-safe properties.
technology / protocolStatus/settings output. Prefer NordLynx as the planned default.
countriesNormalized model from nordvpn countries, refreshed at startup and on demand.
isUpdating / lastErrorShared mutation/read feedback pattern matching Tailscale.
connect(countryCode, mode)Quick: nordvpn connect [country]. P2P: nordvpn connect --group p2p [country].
disconnect()nordvpn disconnect.
login()nordvpn login, then browser flow; panel shows pending login guidance.
setTechnology(value)nordvpn set technology NordLynx|OpenVPN; disconnect/reconnect requirement shown before mutation.

Refresh strategy

Start with a guarded timer because the documented CLI does not expose a stable public event stream equivalent to tailscale debug watch-ipn. Poll status every 5 seconds only while the provider page is visible, every 20 seconds while NordVPN is connected elsewhere in the shell, and stop when disabled/unavailable. Trigger immediate refresh after each mutation and when the panel opens.

Parser hardening

  • Centralize output parsing in pure functions; keep raw CLI text out of UI components.
  • Match labels defensively and tolerate missing/reordered lines, localized output, and new fields.
  • Capture synthetic fixtures only. This public repo must not contain account names, assigned IPs, or real server history.
  • If NordVPN v5 exposes a machine-readable or daemon IPC surface during implementation, prefer it after verifying stability; do not scrape the GUI.

6 · Country and flag model

The CLI provides country names but may not provide ISO codes. Create a small, auditable mapping from NordVPN’s normalized country tokens to ISO 3166-1 alpha-2 codes, then render flags without network access.

{
  "cliName": "United_States",
  "displayName": "United States",
  "countryCode": "US",
  "flag": "🇺🇸",
  "connected": false,
  "supportsP2p": true
}
  • Prefer emoji flags for zero asset overhead. Test glyph availability under the configured Ambxst font; fall back to a two-letter badge when the emoji renders as missing glyphs.
  • Do not hardcode a server-availability catalog. The country list comes from the installed CLI and can change.
  • For v1, the P2P badge means “selectable in P2P optimized mode,” not a live speed guarantee. If a country-specific P2P request fails, retain the selection and offer global fastest P2P.
  • Search matches display name, ISO code, and CLI token. Sorting uses locale-aware display names.

8 · Phased delivery

01Recon on the Bostrom lab

Install dependencies explicitly (never use the repo’s forbidden installer paths), add the session user to the NordVPN group if required, reboot/log out if required, and capture redacted outputs for version, status, settings, countries, and groups. Confirm v5 CLI syntax before coding.

02Provider service and fixtures

Build NordVpnService, pure parsers, country mapping, availability/login states, and read-only refresh. Test with synthetic output fixtures before any connection mutation.

03Standalone NordVPN panel

Add the provider card, routed submenu, Quick Connect, country search/flags, Fastest/P2P modes, and settings-index entries. Match TailscalePanel sizing, scroll reset, titlebar anchoring, null safety, and privacy behavior.

04Serialized provider handoff

Add VpnService, confirmation UI, timeouts, error recovery, and explicit route-owner messaging. Validate Tailscale peer access and internet egress after every transition.

05Optional tray integration

Only after settings behavior is stable, generalize the current Tailscale tray entry into a VPN status entry or add a NordVPN sibling. Avoid two competing always-visible VPN icons by default.

9 · Test protocol

Service

  • CLI missing, daemon stopped, logged out
  • Connected/disconnected/transitional parsing
  • Country names with spaces/underscores
  • Mutation timeout and non-zero exit
  • No overlapping Process mutations

Interface

  • 480 px full settings and compact popup width
  • Empty, filtered, long-country-list states
  • Emoji flag and ISO fallback glyph
  • Keyboard focus/search and scroll reset
  • Theme variants; no hardcoded QML colors/sizes

Routing

  • Tailscale → NordVPN and reverse handoff
  • Cancel before handoff
  • Disconnect success + target failure
  • External CLI state change reflected
  • DNS, LAN, MagicDNS, and peer reachability

Safety

  • Kill switch behavior during transition
  • Closed settings panel during mutation
  • Quickshell restart while connected
  • Sandboxed HOME under lab/
  • No personal data in logs or fixtures

11 · Acceptance criteria

  • VPN settings shows distinct, live Tailscale and NordVPN provider cards and routes directly to either submenu.
  • NordVPN can Quick Connect, disconnect, search/select a flagged country, and request Fastest or P2P-optimized routing.
  • Switching providers is serialized, confirmed by default, visibly staged, timeout-bounded, and recoverable on failure.
  • The panel correctly handles CLI missing, daemon unavailable, login required, empty country list, and external state changes.
  • No credentials or personal network data are persisted or committed.
  • All QML uses Ambxst styling/config/service conventions; every new config key exists in both required config locations.
  • Lab validation covers Tailscale reachability, public egress, DNS, LAN access, kill switch, and shell restart behavior.
Official CLI basis checked for this plan NordVPN’s Linux CLI documentation currently lists status, countries, connect, disconnect, connect --group p2p <country>, technology selection, and kill-switch settings. The official open-source Linux client repository documents NordLynx/WireGuard, OpenVPN, firewall, routing, and DNS responsibilities. Re-verify against the installed Bostrom version during Phase 1.
